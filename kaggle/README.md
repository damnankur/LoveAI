# loveAI — Kaggle Training (free tier)

Train the persona model on **Kaggle's free GPU quota (30 GPU-hours/week, T4/P100)** — no card, no Colab limits. This sidesteps the local GTX 1650 Ti (4 GB) and the sub-agent permission wall.

## What's here

```
kaggle/
├── loveai-persona-train.ipynb   ← the training notebook (setup → data → SFT → DPO → merge → smoke test)
└── loveai-persona-data/          ← dataset bundle (upload as a Kaggle Dataset)
    ├── dataset-metadata.json     ← Kaggle metadata + full data card
    ├── persona_sft_train.jsonl   (4,680 rows) / persona_sft_val.jsonl   (520)
    ├── persona_dpo_train.jsonl   (4,680 rows) / persona_dpo_val.jsonl   (520)
    ├── persona_prompts.jsonl     (200 persona system prompts, for merging extra data)
    ├── dataset_report.json       (seed, counts, quality gate, dataset license registry)
    └── persona-matrix.json
```

Current bundle = **26 scenario prompts × 200 personas** (was 12 prompts × 200), deterministic (`--n 200 --seed 42`). Regenerate with:

```bash
python ml/datasets/build_dataset.py --n 200 --seed 42 --out-dir kaggle/loveai-persona-data
```

## Steps (15 min)

### 1. Create the Dataset
- kaggle.com → **Create → New Dataset** → upload the contents of `loveai-persona-data/`, name it `loveai-persona-data`.
- (Optional, API route: add `"id": "<your-username>/loveai-persona-data"` to `dataset-metadata.json` and `kaggle datasets create -p kaggle/loveai-persona-data`.)
- Wait for the dataset to be live (a minute).

### 2. Create the Notebook
- **Create → New Notebook** (or **File → Import** with `loveai-persona-train.ipynb`).
- **Settings (right panel):**
  - Accelerator: **GPU T4 x2** (or P100)
  - Internet: **ON** (model download + `pip install` — the first cell installs `trl`/`peft`/`bitsandbytes`, which Kaggle's base image doesn't ship)
  - Language: Python
- **Add Input:** your `loveai-persona-data` dataset, plus **any** of the optional real-dialogue datasets below.
- **HF token:** only if you train `google/gemma-3-1b-it` (gated — add the `HF_TOKEN` secret after accepting the license). `Qwen/Qwen2.5-1.5B-Instruct` needs no token.

### 3. Optional inputs — real conversational data

The notebook auto-detects whatever you add under `/kaggle/input`: it sniffs the conversational columns, applies the same quality gate as `ml/datasets/build_dataset.py` (safety/clinical/length), injects a persona system prompt from `persona_prompts.jsonl`, and merges the result into the SFT set (capped at 4,000 rows so the synthetic voice data is never swamped). Missing inputs are skipped silently.

Ranked by value for an empathetic, persona-based companion:

| # | Kaggle input (slug) | License | Adds | Themes |
|---|---|---|---|---|
| 1 | `asifahnafchowdhury/empathetic-dialogues-dataset-by-rashkin-cleaned` | research-only (CC-BY-NC upstream) | 24.8k empathy conversations, 32 emotions | all 12 core themes |
| 2 | `nbertagnolli/counsel-chat` | unclear / CC0 copy | 2,775 licensed-therapist Q/A | relationships, anxiety, self-esteem, family |
| 3 | `thedevastator/amod-mental-health-counseling-conversations-data` or `melissamonfared/mental-health-counseling-conversations-k` | RAIL-D (non-commercial) | counseling Q/A pairs | relationships, stress, anxiety |
| 4 | `antengage/empathy-conversation-dataset` | see dataset page | 4,008 multi-turn empathy conversations | grief, caregiver burnout, loneliness, workplace stress |
| 5 | HuggingFace at runtime: `thu-coai/esconv`, `google/Synthetic-Persona-Chat`, `allenai/soda`, `fadodr/mental_health_therapy` | CC-BY-NC-4.0 / CC-BY-4.0 / CC-BY-4.0 / MIT | support strategies, persona-conditioned small talk, 1.5M social dialogues | small talk, everyday check-ins |

Notes:
- The HuggingFace sources are wired into the **repo** builder (`--real-data`), not into the notebook. To bake them into the bundle, run the repo command below on a machine with internet, then re-upload the bundle:
  ```bash
  python ml/datasets/build_dataset.py --real-data all --out-dir kaggle/loveai-persona-data
  ```
- **License discipline:** the bundle is synthetic-only on purpose (nothing third-party to redistribute). Datasets marked non-commercial/RAIL-D are fine for personal research; they are **not** fine for a paid product. `--real-data permissive` limits the repo builder to Apache/MIT/CC-BY sources.
- The notebook merges extra data into **SFT only**. Persona-contrasted DPO pairs are generated by `ml/datasets/templates.py`; run the repo builder if you want real-data DPO pairs baked in.

### 4. Run
- **Run All**. Expected: SFT ~minutes, DPO ~minutes, merge ~2-4 min, smoke test ~1 min.
- Outputs land in `/kaggle/working/`:
  - `persona-sft/`, `persona-dpo/` (adapters — small)
  - `persona-merged/` (~3 GB — **the deployable model**)
  - `sample-reply.txt` (a persona-grounded reply to eyeball)

### 5. Download + deploy
- Download `persona-merged/` from the **Output** tab.
- Next step: GGUF export → HF CPU Space or AWS free tier → `LLM_URL` in Vercel (see `Knowledge/loveai-free-live-plan.md`).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `403`/`gated`/`401` downloading the model | Accept the Gemma license + set the `HF_TOKEN` secret, or switch `BASE_MODEL` to `Qwen/Qwen2.5-1.5B-Instruct` (not gated) |
| `FileNotFoundError: persona_sft_train.jsonl` | Add the `loveai-persona-data` dataset under **Add Input** |
| `ModuleNotFoundError: No module named 'trl'` | Make sure **Internet: ON** and run the install cell |
| `datasets` fails loading HF datasets | Only relevant if you call `load_dataset` in the notebook; the Kaggle inputs (`/kaggle/input/...`) need no downloads |
| OOM | Use T4 x2 (16 GB) — 1B QLoRA fits easily; drop `gradient_accumulation_steps` to 4 |
| `Column ... not found` from `remove_columns` | Don't add extra keys to the JSONL rows (see schema in `dataset-metadata.json`); use `--with-provenance` only for analysis builds |
| Import fails | Create a fresh notebook and paste cells; kernelspec mismatch is cosmetic |

## Repo parity

The notebook mirrors `ml/train.py` → `ml/train_dpo.py` → `ml/merge.py` → `ml/serve.py` (same hyperparams, same LoRA target modules, same compute-dtype logic). Anything you change in the notebook, mirror back into the repo scripts so train/serve stay consistent.

Row schemas are strict on purpose: SFT rows are exactly `{persona_id, messages}`, DPO rows exactly `{persona_id, prompt, chosen, rejected}`, so `ml/train_dpo.py`'s `remove_columns` and `ml/train.py`'s `remove_unused_columns=False` keep working untouched. Validate any new build with the checks in the brief (schema, split disjointness, crisis/clinical scan).
